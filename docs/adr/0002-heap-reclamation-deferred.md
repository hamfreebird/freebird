# ADR 0002：Stardust 堆回收（M1-3）

- 状态：已实施简化方案（2026-11-22）
- 相关：`docs/adr/0001-logical-remote-stack.md`、`src/codegen/stardust.rs`、ROADMAP M1-3

## 背景

M1-3 要求 Stardust 后端的堆块可释放/复用，使长循环中的分配不会让
`HEAP_ALLOC_PTR` 无限增长，并让 `DropVar` 不再是空操作。

当前 Stardust 后端的堆块语义是**值语义 + copy-on-write**：

- `let b = a;` 让两个变量共享同一个块句柄；
- 写入 `a[i] = v` / `a.push(v)` / 字段赋值时，先克隆旧块，再把变量重绑到新块；
- 其他别名变量仍持有旧块。

因此一个块可能被多个变量、函数参数、返回值或容器元素同时引用。直接释放
会产生 use-after-free。完整引用计数需要覆盖所有句柄复制点（栈复制、容器
元素、函数传参/返回），本轮采用一个保守但安全的子集。

## 已实施

1. **free list 分配器**：块布局保持 `[len, cap, elems...]`。空闲块用
   `len = -1` 标记，`cap` 存块大小（含头部），`elems[0]` 存下一个空闲块
   地址。分配器优先复用满足大小的空闲块，否则推进 bump 指针。
2. **Vec 原地操作**：`Vec` 是 Move 类型，借用检查拒绝别名 push/pop。
   `VecPush` 在容量足够时原地追加，容量不足时按 2 倍扩容并释放旧块；
   `VecPop` 原地缩减。长循环 push 从 O(n²) 堆增长降为 O(n)。
3. **空容器预留容量**：`Vec::new()` / 空数组字面量分配 4 个容量槽，
   使循环内创建/销毁的 Vec 能复用同一块；100/1000 次循环的
   `HEAP_ALLOC_PTR` 稳定在 22。
4. **DropVar 保守回收**：Stardust 后端跟踪已知持有 Move 堆块的绑定
   （Vec 通过 push/pop、Box 通过 `MakeBox`）。`DropVar` 在绑定未被返回
   或别名引用时释放块；函数实参与返回值的所有权转移会清除调用者的标记。

## 限制（仍需完整引用计数/所有权跟踪）

- 数组/结构体/枚举是 Copy 类型，可能被别名共享；`IndexStore` / `FieldStore`
  的写时复制旧块不会释放，长循环写入仍可能增长。
- 容器元素中的嵌套句柄不递归释放；`Vec<Vec<T>>` 的内层块会泄漏。
- 从未 push/pop 的 `Vec` 字面量、`String` 与普通数组不标记为可回收，
  `DropVar` 不会释放它们（安全泄漏）。
- 这些限制不会导致 use-after-free；借用检查保证 Move 类型在操作时独占。

## M6-2.5 堆压力测量（2026-11-25）

压力程序（Stardust 后端）：循环 N 次

```rust
let mut a = [i, i + 1, i + 2];
a[0] = acc;
```

每次 `IndexStore` 触发写时复制、旧块不释放；末尾用 `stardust! { DumpState }`
读取解释器的 `HeapSize`：

| N | HeapSize（堆元素） |
|---|---|
| 100 | 1011 |
| 500 | 5011 |
| 1000 | 10011 |
| 2000 | 20011 |

结论：

- 增长严格线性，约 **10 个堆元素/次** COW 写入（3 个数组元素 + 块头/容量开销）。
- 默认堆上限 `DEFAULT_HEAP_SIZE = 1_048_576` 元素 → 约 **10 万次**写入后耗尽；
  在此之前正确性不受影响（不回收不会 use-after-free），但长循环写入最终会触顶报错。
- 因此 M6-2.5 **明确维持保守策略**，把上述上限作为已知边界记录；完整回收仍按
  「后续」推进。回归护栏：
  `tests/m6_test.rs::stardust_heap_growth_is_bounded_under_cow_pressure`
  （1000 次迭代约 1 万元素，VM/Stardust 输出一致）。

## 后续

若要把数组/结构体和嵌套容器也安全回收，需要引入完整的引用计数或所有权
跟踪，并在所有句柄复制点维护计数。届时可替换本 ADR 的保守子集。
