# ADR 0002：Stardust 堆回收推迟到引用计数设计（M1-3 遗留）

- 状态：待设计（2026-11-22）
- 相关：`docs/adr/0001-logical-remote-stack.md`、`src/codegen/stardust.rs`、ROADMAP M1-3

## 背景

M1-3 要求 Stardust 后端的堆块可释放/复用，使长循环中的分配不会让
`HEAP_ALLOC_PTR` 无限增长，并让 `DropVar` 不再是空操作。

当前 Stardust 后端的堆块语义是**值语义 + copy-on-write**：

- `let b = a;` 让两个变量共享同一个块句柄；
- 写入 `a[i] = v` / `a.push(v)` / 字段赋值时，先克隆旧块，再把变量重绑到新块；
- 其他别名变量仍持有旧块。

因此一个块可能被多个变量、函数参数、返回值或容器元素同时引用。仅凭
`DropVar { name }`（MIR 中没有类型或引用计数信息）无法判断某个块是否仍然
可达；直接释放会产生 use-after-free。

## 决策

本轮不实现 M1-3。保持堆只增不减，并在 `STATUS.md` / `ROADMAP.md` 中明确标注。

## 候选方案（下一轮评估）

1. **堆块引用计数**（推荐）：在块头增加 refcount，在变量绑定/复制、函数
   传参/返回、容器元素写入时增减；`DropVar` 递减并在 0 时释放。需要覆盖
   所有堆句柄复制点，并用堆压力测试 + use-after-free 负向测试保护。
2. **深拷贝值语义**：每次绑定/传参/返回都深拷贝块，使每个变量独占块，
   `DropVar` 可安全释放。实现较直观，但会改变性能特征，且仍需递归处理
   容器中的嵌套句柄。
3. **作用域竞技场**：按函数/作用域分配和整体释放，需要解决返回值逃逸。
   不推荐，容易与现有 COW 语义冲突。

在选定方案前，不应在受支持路径上引入任何“部分释放”逻辑。
