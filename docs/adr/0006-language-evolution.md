# ADR 0006：语言演进路线（格式化 API、泛型约束与单态化、闭包/const/trait）

> 状态：提案（M6-5，2026-11-25）。**未实施**：本 ADR 只固定设计与分阶段计划，
> 实现按阶段排期，不属于 M6 的完成条件。

## 背景

`ROADMAP.md` 的 M6-5 列出三项语言能力演进，均需要先有 ADR：

- **M6-5.2 字符串格式化 API**：当前只有 `print`/`print_str`/`print_char`、
  `int_to_str` 与 `String` 的 `+` 拼接，没有占位符/插值。
- **M6-5.1 泛型约束与按实例单态化**：`readme.md` §5.5 是类型擦除 MVP——布局与函数
  按基名共用一份，无约束，泛型函数体只能使用与具体类型无关的操作。
- **M6-5.3 闭包、`const`、trait/关联类型**：语法尚不存在（`impl` 已实现，见
  [ADR 0003](0003-user-impl-methods.md)）。

三项都会触及类型检查、MIR、双后端布局与代码生成，必须一次把边界与顺序定清楚，
避免各自为政后返工。

## 决策总览

1. 三条线独立推进，依赖顺序为 **格式化 API → 泛型约束/单态化 → 闭包/const/trait**。
2. 每条线遵循同一闭环：规范（`readme.md`）→ VM 后端 → Stardust/LLVM 后端 →
   `USAGE.md`/`STATUS.md`/`CHANGELOG.md` 同步。
3. 准入门槛：双后端输出一致、诊断稳定、现有类型擦除程序与差分 fuzz corpus 不回归。
4. 不引入宏系统（`format!` 之类的语法级宏）作为前置条件；先用内建函数实现格式化，
   语法糖留到闭包/宏统一设计时再评估。

## 决策 1：字符串格式化 API（M6-5.2，优先）

**语法**：内建函数 `format(template: String, args...) -> String`，模板字面量使用 `{}`
占位符，支持 `{{`/`}}` 转义；`{}` 按实参类型格式化（`i64`/`bool`/`char`/`String`/
实现了格式化约束的复合类型）。

**实现**：

- 新增 `MirInst::Format { argc }`：从栈取模板与实参，拼接到新 `String`（堆块）。
- VM 侧简单直接；Stardust 侧用现有 `String` 堆块（`[len, cap, chars...]`）逐段拼接，
  与 `int_to_str` 共用字符写入辅助。
- 占位符数量与实参数量在**编译期**校验（模板为字面量时）；模板来自变量时退化为
  运行时报错（明确诊断信息），不让静默错位。

**备选方案**：

- 宏 `format!(...)`：需要宏系统与卫生性设计，和 M6-5.3 的闭包/宏规划耦合，暂不选。
- 仅提供 `String::push_str`/`+`：表达力不足，`int_to_str` 拼接冗长，不解决可读性。

**验收**：双后端输出一致（含 `{}` 数量错误诊断）；`USAGE.md` 与 `readme.md` §9 同步；
新增 `format_*` 测试覆盖字面量/变量模板、转义与错误。

## 决策 2：泛型约束与按实例单态化（M6-5.1）

**现状**：类型擦除——`Pair<T>`/`fn id<T>` 只生成一份布局/函数，`impl` 不接受泛型参数。

**设计**：

- **约束语法**：`fn max<T: Ord>(a: T, b: T) -> T`、`struct Pair<T: Display>`。
  第一阶段只接受**内建 trait**（`Ord`/`Eq`/`Display` 等最小集合）；用户自定义 trait
  依赖 M6-5.3。
- **单态化 pass**：类型检查通过后、MIR 生成前，收集所有实例化组合（显式 turbofish
  与推断得到的类型实参），为每个实例生成独立布局与 MIR；Stardust/LLVM 后端按实例
  生成堆块布局与函数体。
- **兼容策略**：**默认仍走类型擦除**（保持现有程序的行为、体积与堆布局不变）；
  声明了约束、或显式标注 `#[monomorphize]` 时才按实例单态化。这样满足
  “不破坏现有类型擦除程序”；提供 `--no-monomorphize` 回退用于排查。
- **诊断**：约束不满足、实例缺失、擦除体使用具体类型相关操作，都在类型检查阶段报错。

**分阶段**：

1. 单态化基础设施：实例收集、按实例布局/函数生成、双后端一致性测试。
2. 约束语法与内建 trait 检查。
3. 与用户 trait（M6-5.3）整合；评估代码体积与基准变化。

**验收**：`Pair<i64>` 与 `Pair<String>` 各自布局正确、互不干扰；约束违反有稳定诊断码；
擦除程序与差分 fuzz 全部通过。

## 决策 3：闭包、`const`、trait/关联类型（M6-5.3，P3）

**闭包**：借用检查器已能分析 `&`/`&mut`；实现先做 `Fn`（不可变捕获）：

- 捕获按值/引用转换为**显式环境结构体** + `fn(env, args...)` 函数指针，
  复用现有 `FnPtr` 间接调用；`FnMut`/`FnOnce` 后续。
- 备选：单态化把闭包提升为顶层函数（依赖 M6-5.1 的第 1 阶段）。

**`const`**：先做编译期求值子集（字面量、算术、比较、`const fn`），复用 MIR 常量
折叠；禁止循环与堆分配；类型检查阶段求值，超限/不支持的表达式明确报错。

**trait/关联类型**：静态分发优先（与 M6-5.1 单态化共享 trait 定义）；
`dyn Trait` + vtable 的动态分发需要堆布局改造，作为后续评估项。

**排期**：M6-5.3 在 M6 内只产出本 ADR 与规范草稿；实现进入后续里程碑。

## 替代方案与取舍

- **全部跳过、维持现状**：实现成本最低，但格式化与泛型约束是用户最常提的表达力缺口。
- **先做 `dyn Trait` 动态分发**：需要 vtable 与堆块布局 overhaul，风险与收益不成比例，暂不选。
- **用宏替换泛型**：会破坏类型检查与借用检查的可诊断性，不选。

## 后果

- 三条线可独立排期；每条线都以“规范 → VM → Stardust/LLVM → 文档”闭环，双后端差分是准入门槛。
- 类型擦除与单态化长期并存，需要显式的开关、测试矩阵与文档说明，避免同一程序在不同
  模式下布局/体积不一致且无人察觉。
- 格式化 API 先落地可为后续诊断/日志类内建（如 `debug_print`）提供基础。

## 已实施

### M6-5.2 字符串格式化（2026-11-25）

- 与决策 1 一致：新增变参内建 `format(template, args...)`，`{}` 依次消费实参，
  `{{`/`}}` 输出字面花括号；实参支持整数、`bool`、`char`、`String`。
- 新增 `MirInst::Format { kinds }`，实参种类在类型检查期确定并随 MIR 交给双后端；
  VM 直接按值格式化，Stardust 先构造字符串块数组再做“统计长度 + 写入字符”两遍扫描，
  LLVM 经 Stardust 继承。三端输出逐字节一致。
- 字面量模板在类型检查期校验占位符数量（T025），实参类型不受支持报 T024；
  变量模板在运行期校验，两端一致地报错。
- 偏离：未实现 ADR 设想的复合类型（结构体等）格式化，当前只覆盖标量/字符串；
  `format` 内部产生的临时堆块按 Stardust 的保守回收策略不释放。
- 测试：`tests/m6_test.rs` 覆盖字面量/变量模板、转义、负数、占位符数量错误、
  不受支持实参类型、运行期不匹配与 LLVM 目标。

### M6-5.1 泛型约束与按实例布局（2026-11-25）

- 约束语法：`<T: Ord + Eq + Display>`，解析为 `GenericParam { name, bounds }`；当前只接受这三个内建 trait。
- 满足关系：整数、`bool`、`char`、`String`；在结构体/枚举字面量与泛型函数调用点校验，不满足报 T026。
- 实例收集：`TypeChecker` 记录「基名 → 类型实参组合」；`TypeTable` 按实例注册布局
  （字段/载荷类型替换），MIR 在构造点按实例查表并回退基名。
- 兼容：未声明约束的程序行为不变；泛型函数体仍按基名共用一份（类型擦除）。
- 偏离/未完成：ADR 阶段 1 的「按实例函数体生成」尚未实施（泛型体只允许类型无关操作，
  当前共用一份 MIR）；用户自定义 trait 依赖 M6-5.3。
- 测试：`TypeTable` 实例布局单元测试；`tests/m6_test.rs` 覆盖约束通过/违反与双后端一致性。

### M6-5.3 用户 trait 约束（2026-11-25）

- `trait Name { fn ...; }` + `impl Trait for Type` 的方法仍按 `Type::name` 扁平化。
- 泛型参数可使用用户 trait 作为约束：HIR 记录 trait 声明与 impl 关系，类型检查在实例化点
  校验实参类型是否有对应 impl，缺失报 T026。
- 未完成：`dyn Trait`/vtable、关联类型、trait 默认方法。
- 测试：`tests/m6_test.rs` 覆盖约束通过与缺失 impl 的拒绝。

- 语法：`|params| body` / `|| body`，参数必须带类型标注。
- 实现：HIR 降级期把闭包提升为顶层函数 `__closure_N`，表达式位置替换为函数指针；
  复用既有 FnPtr/间接调用路径，VM/Stardust/LLVM 一致。
- 约束：捕获外部变量的闭包报 R009；环境结构体与 `fn(env, args)` 调用约定未实现。
- 测试：`tests/m6_test.rs` 覆盖无捕获闭包（直接调用/高阶传参/零参）与捕获拒绝。

- 语法：`const NAME: Type = expr;`（类型标注可省略）。
- 求值子集：字面量、此前的 const、一元/二元算术/比较/逻辑；除零、前向引用、溢出与
  不支持的表达式报 R008。
- 实现：HIR 降级期求值，使用点替换为字面量，因此 VM/Stardust/LLVM 自动一致。
- 未完成：`const fn`、循环/分支求值；闭包语法已解析但在类型检查阶段显式拒绝（T018），
  捕获/环境/调用语义与用户自定义 trait 仍待后续轮次。

### M6-5.3 trait 静态分发（2026-11-25）

- 语法：`trait Name { fn ...; }` 声明方法签名；`impl Trait for Type { ... }` 提供实现。
- 实现：impl 方法沿用现有 `Type::name` 扁平化，调用点复用用户方法解析，属于静态分发。
- 未完成：trait 约束检查、`dyn Trait`/vtable、关联类型；与闭包捕获语义一起留待后续轮次。
- 测试：`tests/m6_test.rs` 的 `traits_dispatch_statically_on_both_backends`。
